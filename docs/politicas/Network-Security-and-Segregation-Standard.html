1. Purpose

This standard describes how the production network of the DistribuiHub platform is segregated and protected, and how network threats are monitored and prevented. It supports the Information Security Policy.

2. Hosting

The platform runs on a dedicated virtual private server hosted by Contabo, in a data center located in the United States. The same server hosts the web application, the API and the database of the platform. Customer data is therefore stored and processed in the United States. The company informs its customers of this in its Privacy Policy (https://log.vgon.com.br/privacidade, section on international transfer), and applies the protections described in this standard and in the Information Security Policy.

3. Network segregation

ControlDescription
Database not exposedThe PostgreSQL database has no port published to the Internet or to the host's public interface. It is reachable only by the platform's own application services through the server's internal network.
Host firewallThe server firewall allows inbound connections only on the two ports required by the service: the web application port (3000) and the API port (3001). All other inbound ports are closed.
Separated servicesThe web application, the API and the database run as separate services; only the web and API services accept connections from outside.
Remote administrationAdministrative access (SSH) is enabled only from a single, fixed company IP address. Connections from any other address are refused.
Tenant separationWithin the database, the data of each customer company is separated by row-level security, so a flaw in one customer's session cannot expose another customer's data. This is an additional layer on top of network segregation.

4. Monitoring and prevention of network and application threats

  • Internal monitoring: the company operates internal monitoring of the platform, covering service availability and server and application logs. Anomalies are reviewed by the Information Security Officer and handled under the Incident Response Policy.
  • Rate limiting: the API limits the number of requests per client over time, in particular on sign-in, account recovery and public endpoints, to reduce brute-force and denial-of-service attempts.
  • Account protection: repeated failed sign-ins temporarily lock the account; optional two-factor authentication is available to every user.
  • Audit trail: sensitive actions (sign-ins, permission changes, integration connections, fiscal and financial operations) are recorded with user, time and customer company. Secrets, tokens and keys are masked in logs.
  • Encrypted channels: user and integration traffic is protected with HTTPS/TLS.
  • Public webhooks: endpoints that receive notifications from sales channels require a secret token in the address and verify the sender's cryptographic signature before processing.

5. Firewall and access change control

  • Only the Information Security Officer or a person designated in writing may change firewall rules, open a port or add an address to the administrative allow-list.
  • Each change records who requested it, the reason and the date, and is removed when no longer needed.
  • Open ports and allowed administrative addresses are reviewed at least quarterly. Any port other than the two service ports, and any administrative address that is no longer required, is closed.
  • Database ports are never opened to the public Internet. Temporary access for maintenance is done through the allowed administrative address and closed afterwards.

6. Responsibilities

The Information Security Officer owns this standard, approves changes to the network and reviews monitoring results. Engineering operates the infrastructure according to this standard. All personnel must report suspected network incidents immediately to suporte@vgon.com.br.
